# 用户授权应用管理接口

本文档面向**已登录的终端用户**，说明用户如何查看自己授权过的第三方应用，以及如何撤销对某个应用的授权。

该文档与各「OAuth 接入文档」的视角不同：接入文档面向 OAuth 接入方，本文档面向用户本人管理自己名下的授权记录。所有接口均位于用户自助面 `/user/**`，只操作当前登录用户自己的数据。

## 1. 通用约定

### 1.1 认证

所有接口都需要携带**用户会话凭证**（登录接口下发的 token），支持两种传法：

```http
Authorization: Bearer <会话token>
```

或

```http
UC-Token: <会话token>
```

服务端从会话中取得用户 `uid`。用户不能通过请求参数指定 uid，接口只作用于当前登录用户名下的授权。

### 1.2 响应格式

成功和业务错误均使用统一 JSON 结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 业务状态码，`200` 表示成功 |
| `msg` | string | 结果说明 |
| `data` | object / array / null | 响应数据 |

调用方应始终检查响应体中的 `code`，不能只判断 HTTP 状态码。

## 2. 查看我授权过的应用列表

```http
GET /user/oauth/grants
Authorization: Bearer <会话token>
```

返回当前用户仍有效的第三方应用授权，**按应用（OAuth 客户端）分组**。响应数组的每一项对应一个授权过的应用：

- 组头：应用 ID 与中文名称。
- 组内 `grants`：该应用下的逐次授权记录（一条 = 一次授权，即一个仍有效的 refresh_token）。
- 列表长度（组数）即当前授权过的应用数量；同应用多次授权会在该应用组内展示多条。
- 组与组之间按该应用最近一次授权时间倒序；组内条目按授权时间倒序。

### 2.1 语义说明

- 数据来自授权台账：每次通过授权码流程签发 refresh_token 时记录一条，直到被吊销或过期。
- 使用 refresh_token **刷新不会产生新记录**：刷新只是换发新的 access_token，不改变授权。
- 已吊销、已过期的记录不返回；过期记录由服务端按过期时间过滤，不依赖定时任务。
- **存量兼容**：本功能上线前已签发的旧令牌没有台账记录，不会出现在列表中，将随各自过期自然失效。

### 2.2 返回字段

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "clientId": "client-a",
      "clientName": "我的博客站",
      "grants": [
        {
          "scope": "user.read,user.email",
          "createdAt": "2026-09-01T10:20:30",
          "expiresInSeconds": 7776000
        },
        {
          "scope": "user.read",
          "createdAt": "2026-07-18T09:00:00",
          "expiresInSeconds": 2592000
        }
      ]
    }
  ]
}
```

组（数组项）字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `clientId` | string | 应用（OAuth 客户端）ID |
| `clientName` | string | 应用中文名称（来自应用注册信息） |
| `grants` | array | 该应用下的授权条目列表，按授权时间倒序 |

`grants` 条目字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `scope` | string | 授权的权限范围，逗号分隔 |
| `createdAt` | string | 授权创建（签发）时间，ISO-8601 格式 |
| `expiresInSeconds` | integer | 该条 refresh_token 剩余有效期（秒），小于等于 0 即视为过期 |

## 3. 撤销我对某应用的授权

```http
POST /user/oauth/grants/revoke
Content-Type: application/json
Authorization: Bearer <会话token>
```

请求体：

```json
{
  "clientId": "client-a"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `clientId` | string | 是 | 要撤销授权的应用（OAuth 客户端）ID，1-128 个字符 |

### 3.1 撤销语义（按应用整体撤销）

该接口**按应用粒度**撤销，不是逐条撤销：

1. 撤销当前用户对 `clientId` 对应应用的**全部授权记录**（同应用多次授权的一次性全部撤销）。
2. 同步作废该应用名下的**全部 refresh_token 与 access_token**，包括撤销前已分发、尚未过期的 access_token。
3. 撤销后该应用在本列表不再出现；已分发的 access_token 立即失效，再次携带其访问用户数据接口将返回未登录（`code=80001`）；使用已吊销的 refresh_token 在 token 端点换发新令牌则返回令牌无效（`code=90009`）。

### 3.2 幂等与越权

- 操作**幂等**：重复调用、或目标应用从未授权过时均返回成功（`code=200`），可直接用于"按钮多次点击 / 重试"。
- 只能撤销**自己名下**的授权；服务端忽略任何与他人 uid 相关的目标。

### 3.3 撤销效果示例（撤销前）

```json
{
  "clientId": "client-a"
}
```

撤销成功后该应用在列表接口（第 2 节）中消失。若用户需要再次使用该应用，需重新走授权流程。

## 4. 错误码

| HTTP | code | 说明 |
| --- | --- | --- |
| 200 | 200 | 操作成功 |
| 400 | 10002 | `clientId` 为空或超长（参数校验失败）；请求体缺失或为非法 JSON 时实际返回 `200 + 40001` |
| 200 | 80001 | 未登录或登录已失效（未携带会话凭证） |

## 5. 与 OAuth 协议端点的关系

- 本系列接口是**用户自助面**（用户管理"我授权了谁"），走用户会话认证。
- 接入方按 OAuth 协议主动吊销令牌应使用协议端点（如 `POST /oauth2/revoke`），两者是不同视角、互不冲突。
- 无论从哪一侧吊销，最终都作用于同一份授权状态：被吊销的 refresh_token 无法再换发 access_token，已吊销应用的资源访问立即失效。
