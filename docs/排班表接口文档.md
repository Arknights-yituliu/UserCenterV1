# 排班表接口文档

## 数据约定

- 排班表内容必须是合法 JSON 数组；数组中的每一项必须是 JSON 对象。
- 排班记录内部字段不固定，客户端可按业务定义字段，例如 `date`、`time`、`status`。
- 保存请求和查询响应中的 `schedule` 都是 JSON 数组，序列化后的 UTF-8 内容最大 30 KB。
- 每个用户最多保存 5 个排班表。
- 创建时省略 `id`；更新时传入现有排班表的 `id`，并以 `schedule` 内容完整覆盖。
- 查询结果按 `updateTime` 倒序排列。

## 接口列表

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/user/schedule/save` | 当前用户会话 | 创建或覆盖更新自己的排班表，`data` 返回排班表 ID。 |
| GET | `/user/schedule/list?username={username}` | 当前用户会话 | 仅允许查询当前用户自己的排班表列表。 |
| POST | `/user/schedule/delete` | 当前用户会话 | 删除自己的排班表。 |
| GET | `/open/schedule/{id}` | 无 | 按 ID 查询完整排班表。 |
| POST | `/oauth2/schedule/save` | OAuth Bearer Token，需 `config.write` scope | 通过 OAuth 创建或覆盖更新当前用户的排班表，`data` 返回排班表 ID。 |
| GET | `/oauth2/schedule/list` | OAuth Bearer Token，需 `config.read` scope | 通过 OAuth 查询当前令牌用户自己的排班表列表。 |
| POST | `/oauth2/schedule/delete` | OAuth Bearer Token，需 `config.write` scope | 通过 OAuth 删除当前用户的排班表。 |

所有接口使用统一响应结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

## 保存排班表

`POST /user/schedule/save`

请求头需携带当前用户会话凭证。直接将 JSON 数组作为 `schedule` 字段的值：

```json
{
  "schedule": [
    {"date": "2026-09-21", "time": "09:00-18:00", "status": "on_duty"}
  ]
}
```

更新时额外传入 `id`：

```json
{
  "id": 123456789,
  "schedule": [
    {"date": "2026-09-22", "time": "09:00-18:00", "status": "on_duty"}
  ]
}
```

成功响应中的 `data` 为排班表 ID：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": 123456789
}
```

## 查询自己的排班表列表

`GET /user/schedule/list?username={username}`

`username` 必须属于当前登录用户。

OAuth 场景：`GET /oauth2/schedule/list`，无需传 `username`，用户取自令牌，令牌须包含 `config.read` scope，返回结构与下方一致。

成功时 `data` 是排班表对象数组：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "id": 123456789,
      "schedule": [
        {"date": "2026-09-21", "time": "09:00-18:00", "status": "on_duty"}
      ],
      "createTime": "2026-09-20T12:00:00",
      "updateTime": "2026-09-20T12:00:00"
    }
  ]
}
```

## 删除排班表

`POST /user/schedule/delete`

请求头需携带当前用户会话凭证。请求体：

```json
{
  "id": 123456789
}
```

成功时 `data` 为 `null`。只能删除当前用户自己的排班表。

## 按 ID 查询完整排班表

公开查询：`GET /open/schedule/{id}`，无需登录。

OAuth 列表、保存与删除：`GET /oauth2/schedule/list`、`POST /oauth2/schedule/save`、`POST /oauth2/schedule/delete`，请求体与用户侧接口完全一致，用户取自令牌，列表须包含 `config.read` scope，保存与删除须包含 `config.write` scope。

查询返回完整排班表对象，结构与列表中的单个对象相同。排班表不存在时返回业务错误。
