# 认证接口

本文档面向接入用户中心的**客户端前端**，说明发送邮箱验证码、注册、登录、找回密码与登出接口。

接口统一位于 `/auth` 下。除 `POST /auth/logout` 需要**登录态**外，其余接口均**无需登录**。所有接口的失败返回（业务错误）均为 HTTP `200` + 响应体 `code`，仅请求参数校验失败返回 HTTP `400` + `code=10002`，调用方必须同时判断二者。

## 1. 通用约定

### 1.1 认证

| 接口 | 是否需要登录态 |
| --- | --- |
| `POST /auth/send-code` | 否 |
| `POST /auth/register` | 否 |
| `POST /auth/login` | 否 |
| `POST /auth/reset-code` | 否 |
| `POST /auth/reset-password` | 否 |
| `POST /auth/logout` | 是 |

需要登录态的接口须携带**用户会话凭证**（登录接口下发的 `token`），支持两种传法：

```http
Authorization: Bearer <会话token>
```

或

```http
UC-Token: <会话token>
```

凭证缺失、会话记录不存在或已被吊销时返回 `code=80001`。

### 1.2 来源客户端标识（UC-Client-Id）

`POST /auth/register` 与 `POST /auth/login` 会读取请求头 `UC-Client-Id` 并写入会话：

```http
UC-Client-Id: <客户端标识>
```

该值表示"用户从哪个客户端登录"，会随会话保留，供用户自助面接口（如 `/user/config/list`）按来源客户端隔离数据使用。**非必填**；缺省时会话中的客户端标识为空。若后续要调用依赖该标识的接口，请求登录时请务必携带。

### 1.3 验证码约定

- 验证码为 **6 位数字**，写入 Redis 后 **5 分钟**（300 秒）过期。
- 验证码**一次性使用**：校验通过后立即删除；同一验证码不能重复使用。
- 发送限流（两个维度独立计数）：
  - 同一 IP：**60 秒**内只能发送一次；
  - 同一邮箱：**300 秒**（5 分钟）内只能发送一次。
- 超限均返回 `code=30003`。

### 1.4 响应格式

成功和业务错误均使用统一 JSON 结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 业务状态码，`200` 表示成功 |
| `msg` | string | 结果说明 |
| `data` | object / null | 响应数据 |

## 2. 发送邮箱验证码

```http
POST /auth/send-code
Content-Type: application/json
```

### 2.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | string | 是 | 目标邮箱，须为合法邮箱格式 |
| `usage` | string | 是 | 验证码用途，枚举值：`register` / `login` / `reset`，其他值一律拒绝 |

### 2.2 请求示例

```json
{
  "email": "user@example.com",
  "usage": "register"
}
```

### 2.3 行为说明

- `usage=register` 时，服务端**发信前先校验邮箱是否已被注册**：已注册则直接返回 `code=20003`，不发信，也不占用该邮箱的发送间隔额度，用户可立即改用其他邮箱或转去登录。
- 不同 `usage` 使用不同的邮件模板。

### 2.4 成功响应

HTTP `200`，`data` 为 `null`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

### 2.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | `email` 缺失或格式错误、`usage` 不在白名单内 |
| `200` | `20003` | 用途为 `register` 且邮箱已被注册 |
| `200` | `30003` | 同 IP 或同邮箱发送过于频繁 |
| `200` | `40002` | 邮件发送失败 |
| `200` | `40001` | 服务端内部错误 |

## 3. 注册

```http
POST /auth/register
Content-Type: application/json
UC-Client-Id: <客户端标识>
```

注册成功后**自动登录**，响应体与登录接口一致。

### 3.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | string | 是 | 邮箱（登录账号），须先通过 `usage=register` 的验证码验证 |
| `userName` | string | 是 | 用户名，仅允许字母、数字、下划线，长度 3-20 位 |
| `password` | string | 是 | 密码，6-32 位，仅允许数字、字母、`@`、下划线 |
| `verificationCode` | string | 是 | 邮箱验证码（6 位数字） |
| `nickname` | string | 否 | 昵称，最长 24 位，仅允许中文、英文、数字；缺省时取 `userName` |

### 3.2 请求示例

```json
{
  "email": "user@example.com",
  "userName": "orange_user",
  "password": "Passw0rd_",
  "verificationCode": "123456",
  "nickname": "小橘子"
}
```

### 3.3 关键行为

- 服务端**先校验邮箱验证码，再做唯一性校验**。因此探测某邮箱或用户名是否已被占用，必须先持有该邮箱收到的验证码。
- 注册前按来源 IP 与邮箱双维度限流：同一 IP **每小时最多 10 次**、同一邮箱 **每小时最多 3 次**，超限返回 `code=30005`。
- 密码以 BCrypt 加密落库。

### 3.4 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "token": "0f8c2a5e9b1d4c7e8a6f3b2d1e0c9a8b",
    "uid": 1234567890123456789,
    "nickname": "小橘子",
    "avatar": null,
    "email": "u***@example.com"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `token` | string | 用户会话凭证，前端应自行保存并用于后续 `Authorization: Bearer` / `UC-Token` |
| `uid` | integer | 用户 uid |
| `nickname` | string | 昵称 |
| `avatar` | string / null | 头像地址 |
| `email` | string | 邮箱，**已脱敏** |

会话有效期默认 180 天。服务端不限制同一用户的登录设备数。

### 3.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | 字段缺失或格式不符（邮箱、用户名、密码规则、验证码为空等） |
| `200` | `30001` | 验证码错误 |
| `200` | `30002` | 验证码已过期或未发送 |
| `200` | `30005` | 注册请求过于频繁（IP 或邮箱维度） |
| `200` | `20003` | 该邮箱已被注册 |
| `200` | `20007` | 该用户名已被注册 |
| `200` | `40001` | 服务端内部错误 |

## 4. 登录

```http
POST /auth/login
Content-Type: application/json
UC-Client-Id: <客户端标识>
```

支持两种登录方式，由 `accountType` 指定。

### 4.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `accountType` | string | 是 | 登录方式：`password`=账号密码，`email`=邮箱验证码 |
| `userName` | string | 否 | 用户名；`accountType=password` 时与 `email` 二选一，**优先取 `userName`** |
| `email` | string | 否 | 邮箱；`accountType=password` 且未传 `userName` 时作为账号；`accountType=email` 时必填 |
| `password` | string | 否 | 密码；`accountType=password` 时必填 |
| `verificationCode` | string | 否 | 邮箱验证码；`accountType=email` 时必填 |

> `accountType` 仅支持 `password` 与 `email`，其他值返回 `code=10001`（不支持的登录方式）。

### 4.2 密码登录示例

```json
{
  "accountType": "password",
  "userName": "orange_user",
  "password": "Passw0rd_"
}
```

也可用邮箱登录（历史前端只传 `email` 时兼容）：

```json
{
  "accountType": "password",
  "email": "user@example.com",
  "password": "Passw0rd_"
}
```

密码登录行为：

- 账号同时按**用户名或邮箱**匹配。
- **失败计数与锁定**：连续失败达到 **5 次**后，该账号被临时锁定 **900 秒**（15 分钟），期间返回 `code=30004`；登录成功后清零。
- 用户不存在也会累计失败次数，防止撞库探测；用户不存在返回 `code=20001`，密码错误返回 `code=20002`。

### 4.3 邮箱验证码登录示例

```json
{
  "accountType": "email",
  "email": "user@example.com",
  "verificationCode": "123456"
}
```

邮箱验证码登录行为：

- 校验验证码（错误 `30001`、过期 `30002`）。
- **未注册的邮箱会自动注册**：自动创建用户，`nickname` 取邮箱，不设置用户名与密码。
- 自动注册出来的用户如需设置用户名/密码，请使用注册流程或找回密码流程补齐。

### 4.4 成功响应

HTTP `200`，结构同 [3.4](#34-成功响应)（`data` 为 `LoginVO`，含 `token`、`uid`、`nickname`、`avatar`、脱敏 `email`）。

### 4.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | `accountType` 缺失 |
| `200` | `10001` | `accountType` 不是支持的登录方式；密码登录时账号或密码为空 |
| `200` | `20001` | 用户不存在 |
| `200` | `20002` | 密码错误 |
| `200` | `20004` | 账号已被封禁 |
| `200` | `30001` | 验证码错误 |
| `200` | `30002` | 验证码已过期或未发送 |
| `200` | `30004` | 登录失败次数过多，账号已临时锁定 |
| `200` | `40001` | 服务端内部错误 |

## 5. 发送重置密码验证码

```http
POST /auth/reset-code
Content-Type: application/json
```

向账号**已绑定的邮箱**发送重置密码验证码，无需登录。

### 5.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | string | 是 | 账号，邮箱或用户名 |

### 5.2 请求示例

```json
{
  "account": "orange_user"
}
```

### 5.3 行为说明

- 账号不存在返回 `code=20001`；账号未绑定邮箱返回 `code=20006`。
- 验证码发送到该账号绑定的邮箱（而非请求中传入的地址），发送限流规则同 [1.3](#13-验证码约定)（同 IP 60 秒、同邮箱 300 秒）。

### 5.4 成功响应

HTTP `200`，`data` 为 `null`。

### 5.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | `account` 缺失 |
| `200` | `10001` | `account` 为空 |
| `200` | `20001` | 用户不存在 |
| `200` | `20006` | 该账号未绑定邮箱 |
| `200` | `30003` | 发送过于频繁 |
| `200` | `40002` | 邮件发送失败 |
| `200` | `40001` | 服务端内部错误 |

## 6. 重置密码

```http
POST /auth/reset-password
Content-Type: application/json
```

通过邮箱验证码重设密码，无需登录与旧密码。

### 6.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | string | 是 | 账号，邮箱或用户名 |
| `code` | string | 是 | 邮箱验证码（由 [5. 发送重置密码验证码](#5-发送重置密码验证码) 下发） |
| `newPassword` | string | 是 | 新密码，6-32 位，仅允许数字、字母、`@`、下划线 |

### 6.2 请求示例

```json
{
  "account": "orange_user",
  "code": "123456",
  "newPassword": "NewPassw0rd_"
}
```

### 6.3 行为说明

- 验证码校验针对**账号绑定的邮箱**，校验通过后立即失效（一次性）。
- 重置成功后，该用户的**全部会话被踢出**，需重新登录。

### 6.4 成功响应

HTTP `200`，`data` 为 `null`。

### 6.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | 字段缺失或新密码格式不符 |
| `200` | `10001` | `account` 为空 |
| `200` | `20001` | 用户不存在 |
| `200` | `20006` | 该账号未绑定邮箱 |
| `200` | `30001` | 验证码错误 |
| `200` | `30002` | 验证码已过期或未发送 |
| `200` | `40001` | 服务端内部错误 |

## 7. 登出

```http
POST /auth/logout
Authorization: Bearer <会话token>
```

删除当前会话记录。会话状态实时存储于 Redis，删除后该 token 立即失效。

### 7.1 成功响应

HTTP `200`，`data` 为 `null`。

### 7.2 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `200` | `80001` | 未登录或登录已失效 |

登出需先通过登录态校验：凭证缺失或已失效时返回 `code=80001`，此时前端可直接清理本地凭证。删除成功后的会话不可再用。

## 8. 常见错误总览

| `code` | 含义 | 出现场景 |
| --- | --- | --- |
| `10001` | 参数错误 | 登录方式不支持、账号或密码为空 |
| `10002` | 参数校验失败 | 必填字段缺失、格式不符 |
| `20001` | 用户不存在 | 登录/找回密码时账号不存在 |
| `20002` | 密码错误 | 密码登录密码不匹配 |
| `20003` | 该邮箱已被注册 | 注册发码或注册时邮箱已占用 |
| `20004` | 账号已被封禁 | 账号状态为封禁 |
| `20006` | 该账号未绑定邮箱 | 找回密码时账号无邮箱 |
| `20007` | 该用户名已被注册 | 注册时用户名已占用 |
| `30001` | 验证码错误 | 验证码不匹配 |
| `30002` | 验证码已过期 | 验证码未发送或已过期 |
| `30003` | 验证码发送过于频繁 | 同 IP / 同邮箱发送间隔未到 |
| `30004` | 登录失败次数过多，账号已临时锁定 | 连续密码错误达到阈值 |
| `30005` | 请求过于频繁 | 注册 IP / 邮箱维度限流 |
| `40002` | 验证码发送失败 | 邮件服务异常 |
| `40001` | 系统繁忙，请稍后再试 | 稍后重试并保留请求信息 |
| `80001` | 未登录或登录已失效 | 登出时凭证缺失或失效 |

完整错误码见《错误码参考》。
