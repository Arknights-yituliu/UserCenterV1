# 用户配置接口（用户侧）

本文档面向**已登录的终端用户**，说明用户如何保存、读取、删除自己的配置并查询配额。

接口位于用户自助面 `/user/config`，只操作当前登录用户自己、且属于**当前登录客户端**的配置。用户身份取自会话的 `uid`，客户端标识取自会话的 `client_id`，二者均**不能通过请求参数指定或覆盖**。

本文档与《OAuth 用户配置接口文档》为同一份业务的两侧入口，差异见 [1.3](#13-与-oauth-版的差异)。

## 1. 通用约定

### 1.1 认证

所有接口都需要携带**用户会话凭证**（登录接口下发的 token），支持两种传法：

```http
Authorization: Bearer <会话token>
```

或

```http
UC-Token: <会话token>
```

服务端从会话中取得用户 `uid` 与来源 `client_id`。凭证缺失、会话记录不存在或已被吊销（含被踢下线）时返回 `code=80001`——会话状态实时读取，因此"踢下线"立即生效。

### 1.2 数据约定

- 配置按 `uid + client_id + category + version + name` 唯一标识，同一用户在不同客户端下的配置相互隔离。
- `client_id` 来自登录时请求头 `UC-Client-Id`（见《认证接口文档》），**前端不可指定**；登录时未携带该头会导致写入时报 `code=10001`。
- `config` 为 JSON 对象或 JSON 字符串；序列化后的 UTF-8 内容计入用户配置配额。
- 用户配置默认配额 **500 KB**（512000 字节），以用户为单位统计其在**全部客户端**下的配置总量。
- 查询结果按 `updateTime` 倒序排列。

### 1.3 与 OAuth 版的差异

| 维度 | 本文档（用户侧） | OAuth 用户配置接口文档 |
| --- | --- | --- |
| 路径前缀 | `/user/config` | `/oauth2/config` |
| 凭证 | 用户会话 token | OAuth access_token |
| 授权范围 | 不需要 scope | 读取 `config.read`，写入 `config.write` |
| `client_id` 来源 | 会话中的来源客户端 | 令牌中的 OAuth 客户端 |
| 请求体 / 响应体 / 错误码 | 与 OAuth 版完全一致 | — |

### 1.4 响应格式与错误返回

成功和业务错误均使用统一 JSON 结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 业务状态码，`200` 表示成功 |
| `msg` | string | 结果说明 |
| `data` | object / array / null | 响应数据 |

本接口族两类错误的 HTTP 状态不同，调用方必须同时判断 HTTP 状态与响应体 `code`：

| 错误类型 | HTTP 状态 | `code` | 示例 |
| --- | --- | --- | --- |
| 请求内容不合法（字段缺失、格式错误、身份字段被修改、缺少 `id` / `expectedHash`） | `400` | `10002` | save-if-match 未携带 `expectedHash` |
| 业务失败、并发冲突（未登录、配置不存在、配额超限、hash 不一致） | `200` / `409` | `80001` / `10001` / `10004` / `10005` | 并发覆盖冲突 |

## 2. 保存配置（无条件创建 / 覆盖更新）

```http
POST /user/config/save
Content-Type: application/json
Authorization: Bearer <会话token>
```

该接口为普通保存，不做并发控制：

- `id` 为空（省略或传 `null`）→ 新建配置。
- `id` 非空 → 按 `id` 直接覆盖更新（last-write-wins）：不校验内容 hash，`expectedHash` 携带也会被忽略。

需要防止并发覆盖请改用 `POST /user/config/save-if-match`（见 [3](#3-条件更新配置save-if-match防并发覆盖)）。

### 2.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer / null | 否 | 为空=新建；非空=按 id 覆盖更新，目标必须属于当前用户和当前客户端 |
| `category` | string | 是 | 配置分类，1-32 个字符 |
| `version` | string | 是 | 配置版本，1-32 个字符 |
| `name` | string | 是 | 配置名称，1-32 个字符 |
| `source` | string | 否 | 配置来源，最多 32 个字符 |
| `note` | string | 否 | 备注，最多 32 个字符 |
| `config` | object / string | 是 | 配置内容，不能为 `null` |
| `expectedHash` | string / null | 否 | save 接口不使用：创建时携带非空值返回 HTTP `400`；更新时携带一律忽略 |

### 2.2 创建示例

```json
{
  "id": null,
  "category": "editor",
  "version": "v1",
  "name": "default",
  "source": "web",
  "note": "首次同步",
  "config": {
    "theme": "dark",
    "fontSize": 14
  },
  "expectedHash": null
}
```

创建只会在当前用户、当前客户端下不存在相同 `category + version + name` 的记录时成功。记录已存在时返回 HTTP `409`（`code=10005`），`data.currentHash` 为已存在记录的内容 hash。

### 2.3 覆盖更新示例

```json
{
  "id": 123,
  "category": "editor",
  "version": "v1",
  "name": "default",
  "source": "web",
  "note": "自动同步",
  "config": {
    "theme": "light",
    "fontSize": 16
  }
}
```

覆盖更新按 `id` 直接生效：`category`、`version`、`name` 必须与目标记录一致，否则返回 HTTP `400`。请求中即使携带 `expectedHash` 也会被忽略。目标记录不存在或不属于当前用户、当前客户端时返回 HTTP `409`（`data.currentHash` 为 `null`）。

### 2.4 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": 123,
    "hash": "5f70bf18a08660b84f3f4f4f25c4a32f5f728c01e98b767a7c8a153f67e85972"
  }
}
```

前端应保存响应中的新 `hash`，供后续 save-if-match 或读取使用。

### 2.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | 字段缺失、格式不符、更新时修改了 `category` / `version` / `name`，或创建时携带了非空 `expectedHash` |
| `409` | `10005` | 创建时目标已存在，或按 id 覆盖的目标不存在 |
| `200` | `10001` | 缺少来源客户端标识（登录时未携带 `UC-Client-Id`） |
| `200` | `10004` | 用户配置总量超过配额 |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `40001` | 服务端内部错误 |

## 3. 条件更新配置（save-if-match，防并发覆盖）

```http
POST /user/config/save-if-match
Content-Type: application/json
Authorization: Bearer <会话token>
```

该接口只承担按 `id` 的条件更新，采用 CAS（Compare-And-Set）语义，**不承担创建**：

- `id` 和 `expectedHash` 均必填，缺少任一字段返回 HTTP `400`。
- 仅当目标记录当前的 `content_hash` 等于请求携带的 `expectedHash` 时才会落库并返回新 `hash`。
- hash 不一致（被其他请求先更新）或目标记录已被删除时返回 HTTP `409`（`code=10005`），`data.currentHash` 为服务端最新 hash（已删除则为 `null`）。

### 3.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 读取接口返回的配置 ID，必须属于当前用户和当前客户端 |
| `category` | string | 是 | 配置分类，1-32 个字符，须与原记录一致 |
| `version` | string | 是 | 配置版本，1-32 个字符，须与原记录一致 |
| `name` | string | 是 | 配置名称，1-32 个字符，须与原记录一致 |
| `source` | string | 否 | 配置来源，最多 32 个字符 |
| `note` | string | 否 | 备注，最多 32 个字符 |
| `config` | object / string | 是 | 配置内容，不能为 `null` |
| `expectedHash` | string | 是 | 目标记录的最新 64 位 SHA-256 hash，由读取接口或上次保存响应返回 |

### 3.2 请求示例

```json
{
  "id": 123,
  "category": "editor",
  "version": "v1",
  "name": "default",
  "source": "web",
  "note": "自动同步",
  "config": {
    "theme": "light",
    "fontSize": 16
  },
  "expectedHash": "2b7e151628aed2a6abf7158809cf4f3c762e7160f38b4da56a784d9045190cfe"
}
```

### 3.3 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": 123,
    "hash": "5f70bf18a08660b84f3f4f4f25c4a32f5f728c01e98b767a7c8a153f67e85972"
  }
}
```

### 3.4 冲突响应

HTTP `409 Conflict`：

```json
{
  "code": 10005,
  "msg": "配置已被更新",
  "data": {
    "currentHash": "c19d3f7b40d5d193e6dc1faa4f26b18d73f8a70bff94e59f3d47a50e64f7f031"
  }
}
```

出现冲突时不要直接用旧 hash 重试覆盖：应重新读取配置，根据新内容决定覆盖、合并或提示用户。目标记录已被删除时，`currentHash` 为 `null`。

### 3.5 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | `id` 或 `expectedHash` 缺失，`expectedHash` 非 64 位 SHA-256，或修改了身份字段 |
| `409` | `10005` | hash 不一致、目标不存在或不属于当前用户/客户端 |
| `200` | `10001` | 缺少来源客户端标识 |
| `200` | `10004` | 用户配置总量超过配额 |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `40001` | 服务端内部错误 |

## 4. 查询配置

```http
GET /user/config/list?category=editor&version=v1&name=default
Authorization: Bearer <会话token>
```

### 4.1 查询参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `category` | string | 是 | 配置分类 |
| `version` | string | 否 | 精确匹配配置版本 |
| `name` | string | 否 | 精确匹配配置名称 |

查询结果只包含**当前登录客户端**名下的配置，并按更新时间倒序返回。

### 4.2 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "id": 123,
      "clientId": "example-client",
      "category": "editor",
      "version": "v1",
      "name": "default",
      "source": "web",
      "note": "自动同步",
      "config": {
        "theme": "light",
        "fontSize": 16
      },
      "hash": "5f70bf18a08660b84f3f4f4f25c4a32f5f728c01e98b767a7c8a153f67e85972",
      "createTime": "2026-09-03T10:00:00",
      "updateTime": "2026-09-03T10:05:00"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 配置 ID |
| `clientId` | string | 配置归属的客户端标识 |
| `category` / `version` / `name` | string | 配置身份 |
| `source` / `note` | string / null | 来源与备注 |
| `config` | object | 配置内容 |
| `hash` | string | 当前内容 hash，作为 save-if-match 的 `expectedHash` |
| `createTime` / `updateTime` | string | 创建、更新时间 |

没有匹配记录时 `data` 为 `[]`。

### 4.3 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `200` | `10001` | 缺少来源客户端标识 |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `40001` | 服务端内部错误 |

## 5. 删除配置

```http
POST /user/config/delete
Content-Type: application/json
Authorization: Bearer <会话token>
```

### 5.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 读取接口返回的配置 ID，不能为 `null` |

```json
{
  "id": 123
}
```

删除为**物理删除且不可恢复**；删除成功后，该配置占用的字节数会从用户已用配额中扣除。服务端只允许删除当前用户、当前客户端名下的配置。删除接口不使用 CAS，无需提交 `expectedHash`。

### 5.2 成功响应

HTTP `200`，`data` 为 `null`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

### 5.3 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `400` | `10002` | `id` 缺失 |
| `200` | `10001` | 配置不存在，或不属于当前用户、当前客户端 |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `40001` | 服务端内部错误 |

配置不存在与不属于当前用户/客户端返回同一个 `code=10001`，服务端不区分。

## 6. 查询配额

```http
GET /user/config/quota
Authorization: Bearer <会话token>
```

该接口不需要查询参数。配额以用户为单位统计，包含该用户在**全部客户端**下保存的配置内容，而不是只统计当前客户端。

### 6.1 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "usedBytes": 102400,
    "limitBytes": 512000,
    "remainingBytes": 409600
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `usedBytes` | integer | 当前已使用的配置内容字节数 |
| `limitBytes` | integer | 当前用户的配置总配额字节数 |
| `remainingBytes` | integer | 当前剩余字节数 |

所有数值单位均为 byte。从未保存过配置的用户默认返回：

```json
{
  "usedBytes": 0,
  "limitBytes": 512000,
  "remainingBytes": 512000
}
```

### 6.2 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `40001` | 服务端内部错误 |

## 7. 常见错误总览

| HTTP 状态 | `code` | 含义 | 处理建议 |
| --- | --- | --- | --- |
| `400` | `10002` | 请求字段缺失、格式错误、修改了配置身份字段，或 save-if-match 缺少 `id` / `expectedHash` | 修正请求后重试 |
| `409` | `10005` | save 创建目标已存在、按 id 覆盖的目标不存在，或 save-if-match 携带过期 hash | 重新读取配置并处理冲突 |
| `200` | `10001` | 缺少来源客户端标识，或删除的配置不存在 / 不属于当前客户端 | 重新登录并携带 `UC-Client-Id`；或重新读取配置列表 |
| `200` | `10004` | 用户配置总量超过当前配额 | 删除不需要的配置或申请提额 |
| `200` | `80001` | 未登录或登录已失效 | 重新登录 |
| `200` | `40001` | 服务端内部错误 | 稍后重试并保留请求信息以便排查 |

完整错误码见《错误码参考》。

## 8. 推荐同步流程

### 8.1 防并发条件更新（save-if-match）

1. 调用读取接口获得配置的 `id`、内容和 `hash`。
2. 在本地基于该版本编辑配置。
3. 调用 `POST /user/config/save-if-match`，将读取到的 `id` 和 `hash` 分别作为 `id`、`expectedHash`。
4. 保存成功后，用响应中的新 `hash` 替换本地旧 hash。
5. 收到 HTTP `409` 时重新读取配置，不使用旧 hash 循环重试。

### 8.2 无条件保存（save）

- 新建：调用 `POST /user/config/save`，`id` 为空（省略或传 `null`），可省略 `expectedHash` 或显式传 `null`。
- 覆盖更新：同样调用 `POST /user/config/save`，`id` 传目标配置 ID，无需 `expectedHash`；适合可容忍"最后写入者胜出"的同步场景。
