# 用户游戏数据接口

本文档面向**已登录的终端用户**，说明用户如何查看和维护自己名下的游戏账号与干员数据。

所有接口均位于用户自助面 `/user/ak-accounts`，只操作当前登录用户自己的数据。接口复用 OAuth 侧同一套服务逻辑；用户身份取自会话，**不能通过请求参数指定或覆盖**。

本文档与《OAuth 游戏数据接口文档》功能一一对应，前者面向第三方接入方（access_token），本文档面向用户本人的登录态，差异见 [1.2](#12-与-oauth-版的差异)。

## 1. 通用约定

### 1.1 认证

所有接口都需要携带**用户会话凭证**（登录接口下发的 token），支持两种传法：

```http
Authorization: Bearer <会话token>
```

或

```http
UC-Token: <会话token>
```

服务端从会话中取得用户 `uid` 与来源 `client_id`。凭证缺失、会话记录不存在或已被吊销（含被踢下线）时返回 `code=80001`——会话状态实时读取，不依赖本地缓存，因此"踢下线"立即生效。

### 1.2 与 OAuth 版的差异

同一份业务逻辑，两侧的主要差别：

| 维度 | 本文档（用户侧） | OAuth 游戏数据接口文档 |
| --- | --- | --- |
| 路径前缀 | `/user/ak-accounts` | `/oauth2/ak-accounts` |
| 凭证 | 用户会话 token | OAuth access_token |
| 授权范围 | 不需要 scope，登录即可调用 | 需要 `gama-data.read` / `gama-data.write` |
| 归属判定 | 会话中的 `uid` | 令牌中的 `uid` |
| 账号列表返回 | `akUid` + `createTime` + `updateTime` | 仅 `akUid` |
| 失败返回 | 一律 HTTP `200` + 业务码 | 同左 |

其余请求字段、保存语义、错误码完全一致。

### 1.3 响应格式

成功和业务错误均使用统一 JSON 结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 业务状态码，`200` 表示成功 |
| `msg` | string | 结果说明 |
| `data` | object / array / null | 响应数据 |

本接口族的所有应用内失败——**含请求参数校验失败与登录鉴权失败**——统一返回 HTTP `200` + 业务码，不会返回 HTTP `400`。调用方必须始终检查响应体中的 `code`，不能只判断 HTTP 状态码。

日期时间字段为 ISO-8601 无时区格式，例如 `2026-09-20T12:00:00`。

## 2. 查询已绑定的游戏账号列表

```http
GET /user/ak-accounts
Authorization: Bearer <会话token>
```

返回当前用户已绑定的游戏账号，**按最近一次导入时间倒序**，前端取首条即可默认展示最新导入的账号。响应不含干员正文。

### 2.1 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "akUid": "123456789",
      "createTime": "2026-09-20T10:00:00",
      "updateTime": "2026-09-28T18:30:00"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `akUid` | string | 游戏账号 UID |
| `createTime` | string | 绑定关系创建时间（首次导入该账号数据时） |
| `updateTime` | string | 该账号干员数据最近一次导入时间 |

没有绑定任何游戏账号时 `data` 为 `[]`。绑定关系存在但角色信息缺失的账号不会出现在结果中（绑定关系本身仍保留）。

### 2.2 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `40001` | 服务端内部错误 |

## 3. 全量读取干员数据

```http
GET /user/ak-accounts/operators?akUid={akUid}
Authorization: Bearer <会话token>
```

全量返回该游戏账号的干员数据，星级筛选由调用方完成。读取前先核对归属：`akUid` 必须属于当前登录用户。

### 3.1 查询参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `akUid` | string | 是 | 游戏账号 UID，不超过 32 位可见 ASCII 字符 |

### 3.2 成功响应

HTTP `200`，并携带响应头 `Cache-Control: private, no-cache`（仅允许私人缓存且每次回源校验，不得被公共缓存共享）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "akUid": "123456789",
    "items": [
      {
        "id": "char_002_amiya",
        "recordId": 90001,
        "rarity": 5,
        "level": 80,
        "evolvePhase": 2,
        "mainSkillLevel": 7,
        "skill1": 7,
        "skill2": 10,
        "skill3": 0,
        "equipX": 3,
        "equipY": 0,
        "equipD": 0,
        "equipA": 0,
        "equipB": 0,
        "potentialRank": 2
      }
    ]
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `akUid` | string | 游戏账号 UID |
| `items` | array | 干员记录列表，无数据时为空数组 |
| `items[].id` | string | 稳定干员编码，业务关联请使用该字段 |
| `items[].recordId` | integer | 数据库自增行 ID，仅供排查 |
| `items[].rarity` | integer | 干员星级，`0` 表示未提供 |
| `items[].level` | integer | 干员等级 |
| `items[].evolvePhase` | integer | 精英化阶段 |
| `items[].mainSkillLevel` | integer | 基础技能等级 |
| `items[].skill1` / `skill2` / `skill3` | integer | 技能等级或状态 |
| `items[].equipX` / `equipY` / `equipD` / `equipA` / `equipB` | integer | 各模组数值 |
| `items[].potentialRank` | integer | 潜能等级（不是星级） |

全部数值字段始终返回数字，不会返回 `null`。

### 3.3 失败响应

| HTTP 状态 | `code` | 含义 |
| --- | --- | --- |
| `200` | `80001` | 未登录或登录已失效 |
| `200` | `80008` | 该游戏账号不在当前用户名下 |
| `200` | `10002` | `akUid` 未携带或格式非法 |
| `200` | `40001` | 服务端内部错误 |

查询他人账号与查询不存在的账号返回同一个 `80008`，服务端不区分、不暴露账号是否存在。

## 4. 保存角色信息与干员数据

```http
POST /user/ak-accounts/operators/save
Content-Type: application/json
Authorization: Bearer <会话token>
```

目标游戏账号取自请求体 `playerInfo.akUid`。**当前用户首次上传某个游戏账号时直接建立绑定关系**，无需预订绑定。

### 4.1 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `playerInfo.akUid` | string | 是 | 目标游戏账号 UID，不超过 32 位可见 ASCII 字符 |
| `operators` | array | 是 | 干员数组，不能为空 |
| `operators[].id` | string | 是 | 稳定干员编码，1-64 位可见 ASCII 字符 |
| `operators[].rarity` | integer | 否 | 干员星级，0~6 |
| `operators[].level` | integer | 否 | 干员等级，0~65535 |
| `operators[].evolvePhase` | integer | 否 | 精英化阶段，0~255 |
| `operators[].mainSkillLevel` | integer | 否 | 基础技能等级，0~255 |
| `operators[].skill1` / `skill2` / `skill3` | integer | 否 | 技能等级或状态，0~255 |
| `operators[].equipX` / `equipY` / `equipD` / `equipA` / `equipB` | integer | 否 | 各模组数值，0~255 |
| `operators[].potentialRank` | integer | 否 | 潜能等级，0~255 |

数值字段可以省略、传 `null` 或空字符串，服务端统一按 `0` 落库（与显式传 `0` 等价，**不表示沿用旧值**）。负数或超出上述范围会返回 `code=10002`。

### 4.2 请求示例

```json
{
  "playerInfo": {
    "akUid": "123456789"
  },
  "operators": [
    {
      "id": "char_002_amiya",
      "rarity": 5,
      "level": 80,
      "evolvePhase": 2,
      "mainSkillLevel": 7,
      "skill1": 7,
      "skill2": 10,
      "skill3": 0,
      "equipX": 3,
      "equipY": 0,
      "equipD": 0,
      "equipA": 0,
      "equipB": 0,
      "potentialRank": 2
    }
  ]
}
```

### 4.3 保存语义

- 传入的干员 `id` 已存在则按属性比较后更新，不存在则新增；**请求中未出现的干员不会被删除**。
- 同一个请求中的干员 `id` 不能重复，重复返回 `code=10002`。
- 同一游戏账号 2 秒内只接受一次保存请求，命中限流返回 `code=30006`，建议等待秒数在 `data.retryAfterSeconds` 中。该名额按 `akUid` 计算且**所有绑定该账号的用户共享**，不是按用户各自计数。
- 保存过程遇到唯一键冲突或死锁时，服务端会整事务回滚后重试，最多重试 2 次；仍失败返回 `code=40004`，调用方重试整个请求即可。
- 参数校验通过后才占用限流名额，非法请求不会挤占他人的上传名额。

### 4.4 成功响应

HTTP `200`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "createdCount": 1,
    "updatedCount": 2,
    "unchangedCount": 3
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `createdCount` | integer | 新增记录数 |
| `updatedCount` | integer | 属性实际变化并更新的记录数 |
| `unchangedCount` | integer | 与已存数据完全相同、未写库的记录数 |

三项之和等于本次请求传入的干员记录数。

### 4.5 失败响应

| HTTP 状态 | `code` | 含义 | 处理建议 |
| --- | --- | --- | --- |
| `200` | `80001` | 未登录或登录已失效 | 重新登录 |
| `200` | `10002` | 字段缺失、格式错误、数值越界或干员 `id` 重复 | 修正请求后重试 |
| `200` | `30006` | 该游戏账号上传过于频繁 | 按 `data.retryAfterSeconds` 等待后重试 |
| `200` | `40003` | 限流服务不可用 | 稍后重试 |
| `200` | `40004` | 干员数据保存冲突 | 重试整个请求 |
| `200` | `40001` | 服务端内部错误 | 稍后重试并保留请求信息 |

限流响应示例：

```json
{
  "code": 30006,
  "msg": "该游戏账号上传过于频繁，请稍后再试",
  "data": {
    "retryAfterSeconds": 2
  }
}
```

## 5. 常见错误总览

| `code` | 含义 | 出现场景 |
| --- | --- | --- |
| `80001` | 未登录或登录已失效 | 会话凭证缺失、无效或已过期 |
| `80008` | 无权限操作 | 游戏账号不在当前用户名下 |
| `10002` | 参数校验失败 | 请求字段缺失、格式错误或数值越界 |
| `30006` | 该游戏账号上传过于频繁 | 仅保存接口，等待秒数见 `data.retryAfterSeconds` |
| `40003` | 限流服务不可用 | 稍后重试 |
| `40004` | 干员数据保存冲突，请重试 | 重试整个请求 |
| `40001` | 系统繁忙，请稍后再试 | 稍后重试并保留请求信息 |

完整错误码见《错误码参考》。
