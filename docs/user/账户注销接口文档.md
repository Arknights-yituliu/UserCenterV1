# 账户永久注销

两个入口执行相同的永久删除操作，成功返回后立即退出当前客户端并清除本地凭证。账户 UID 由认证凭证决定，不能通过请求参数指定。

## 用户侧：会话认证

先通过当前会话发送注销专用验证码，邮件只发送到服务端记录的绑定邮箱，不接受客户端指定邮箱：

```http
POST /user/account/send-delete-code
Authorization: Bearer <用户会话 token>
```

随后提交注销：

```http
POST /user/account/delete
Authorization: Bearer <用户会话 token>
Content-Type: application/json

{"code":"123456"}
```

两个接口也支持 `TCL-Token`（兼容 `UC-Token`）。OAuth access_token、refresh_token 和 PAT 不能代替用户会话。

## OAuth2 侧：refresh_token 认证

先凭有效的 refresh_token 发送注销专用验证码，服务端从凭证所属账户读取收件邮箱：

```http
POST /oauth2/account/send-delete-code
Content-Type: application/json

{"refresh_token":"<当前有效的 refresh_token>"}
```

随后凭同一来源客户端的有效 refresh_token 与邮件验证码提交注销：

```http
POST /oauth2/account/delete
Content-Type: application/json

{"refresh_token":"<当前有效的 refresh_token>","code":"123456"}
```

两个接口使用请求体中的 refresh_token 确认账户，不需要会话、access_token、client_id 或 client_secret；也接受 `refreshToken` 字段名。只接受 Redis 中仍有效的 refresh_token，已过期、已吊销或已轮转的旧凭证不能使用，轮转宽限期副本也不能作为注销凭证。仅持有 refresh_token、没有邮箱验证码不能注销。

## 邮箱验证码规则

- `code` 必须为 6 位数字，仅支持当前绑定邮箱；无绑定邮箱返回 `20006`，需先绑定邮箱。
- 验证码有效期 5 分钟，与登录、注册、重置密码等普通验证码隔离，不能互相替代。
- 绑定账户 UID、发送时的邮箱和来源客户端。更换邮箱或更换客户端后，旧码不能通过验证；旧会话的空客户端标识也按独立来源绑定。
- 同一账户只保留最后发送的一条注销验证码；错误达到 5 次后作废。验证成功立即消费，不能重放；上述校验与计数由 `scripts/account-deletion-code-verify.lua` 原子完成。
- 发送沿用现有验证码发送策略：同 IP 每分钟 10 次、每小时 50 次，同邮箱发送间隔 60 秒，与其他用途共用发送额度。
- 数据库或后续会话清理失败时，已经消费的验证码不恢复，需要重新发送后重试。

此操作注销该用户的一图流账户，而不只退出当前应用。调用方应先展示永久注销确认提示，在用户明确确认后调用。

## 删除与保留范围

注销顺序：

1. 锁定用户主记录，校验当前绑定邮箱的注销专用验证码，通过后把注销前的用户资料写入独立的 `user_deletion_audit` 审计表。
2. 仅删除 `ak_account_binding`、`ef_account_binding` 中属于本人的游戏绑定，再删除 `user_info` 主记录；其他用户对相同角色的绑定保留。
3. 按用户会话反向索引清理 Redis 登录会话及会话索引，不扫描 Redis 全库。

其余业务数据全部保留：默认数据来源偏好、用户配置、配置配额、排班表、OAuth 授权范围和授权台账、自定义令牌、PAT、登录日志、用户操作审计、自建 OAuth2 应用及其配置都不删除。无需先删除自建应用；这些应用继续保留原所有者 UID，账户注销后原所有者不能再登录管理。

所有游戏数据正文也保留，包括角色资料、干员养成、物品、皮肤、森空岛快照、手动修改版干员数据、终末地玩家数据和寻访记录；游戏统计结果与寻访导入任务不变。延迟完成的导入任务不能重新建立已注销账户的绑定。

Redis OAuth access_token / refresh_token、授权码、登录票据、授权确认单、轮转记录等不主动删除，仍按原有效期过期。受保护资源接口会检查账户仍存在，因此保留的 OAuth/PAT 凭证和遗漏索引的历史会话也不能继续访问资源；令牌换发同样拒绝已注销账户。

## 注销审计

`user_deletion_audit` 按原 UID 唯一保存邮箱、用户名、头像、昵称、账户状态、原注册 IP、注册时间、最后登录时间，以及注销时间、认证方式（`session` / `oauth_refresh`）、凭证所属客户端 ID。旧会话没有客户端 ID 时该字段为空。密码哈希与任何令牌均不写入审计表。

审计与用户、绑定删除在同一数据库事务中提交；审计写入失败则不删除账户。审计表不参与登录、注册或账户恢复；邮箱和用户名在审计表不设置唯一约束，允许重新注册。建表定义维护在 `src/main/resources/db/schema-user.sql`，启用接口前需确保该表已创建。

审计记录用于追溯成功注销，两个入口均需账户凭证和绑定邮箱的注销专用验证码。

## 响应与错误码

成功响应为 HTTP 200：

```json
{"code":200,"msg":"操作成功","data":null,"success":true}
```

| code | 含义 |
| --- | --- |
| `80001` | 用户会话缺失、无效，或凭证所属账户已不存在 |
| `90009` | refresh_token 无效、已过期、已吊销、已轮转，或所属账户不存在 |
| `10002` | 请求体缺少必填字段，或 code 不是 6 位数字（HTTP 400） |
| `20006` | 当前账户未绑定邮箱，不能发码或注销 |
| `30001` | 验证码错误、绑定信息不匹配或错误次数达到上限 |
| `30002` | 注销验证码不存在、已过期或已消费 |
| `30003` | 验证码发送过于频繁 |
| `20001` | 账户不存在，例如并发注销时另一个请求已经删除账户 |
| `40001` | 注销审计写入失败等系统错误 |

审计和数据库删除在同一事务中执行；Redis 会话清理失败会回滚审计、账户与绑定删除。已经删除的 Redis 会话不会恢复，用户可能需要重新登录后重试。OAuth/PAT 及其他业务记录不因本次清理失败而被撤销或删除。

注销后旧会话、OAuth 令牌和 PAT 均不可继续访问资源；受保护接口在凭证验证后额外检查账户是否存在，阻止注销期间并发生成的残留凭证继续使用。重新注册会创建新账户，不恢复原 UID、配置或绑定。
